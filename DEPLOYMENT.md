# Deployment guide

This repository is prepared for the following deployment layout:

- **Frontend:** Vercel, using `frontend` as the project root.
- **API:** Render, using the repository Blueprint in `render.yaml` and the root `Dockerfile`.
- **Database:** Neon PostgreSQL, connected to the API through Render environment variables.

## 1. Create the Neon database

Create a Neon project and database, then copy the connection details from its dashboard. Neon requires SSL for hosted connections. In Render, set:

- `DB_URL`: `jdbc:postgresql://<host>/<database>?sslmode=require`
- `DB_USERNAME`: the Neon role name
- `DB_PASSWORD`: the password for that role

Use the host, database, username, and password shown by Neon. Keep these values in Render's environment settings; do not commit them or put them in Vercel.

## 2. Deploy the API on Render

Create a Blueprint from this repository and select the branch to deploy. Render will read `render.yaml` and build the root `Dockerfile`.

Set the Blueprint's secret values:

- `DB_URL`, `DB_USERNAME`, and `DB_PASSWORD` from Neon.
- `JWT_SECRET` is generated by Render as a Base64 encoded random value.
- `CORS_ALLOWED_ORIGINS`: the exact Vercel production origin, such as `https://your-project.vercel.app`. Add custom domains as a comma-separated list if needed.

After the service is created, note its public URL, for example `https://codereview-api.onrender.com`. The Blueprint health check uses the public Swagger UI route.

## 3. Deploy the frontend on Vercel

Import the same repository into Vercel and set:

- Root Directory: `frontend`
- Framework preset: Vite
- Install command: `pnpm install --frozen-lockfile`
- Build command: `pnpm build`
- Output directory: `dist`
- Environment variable `VITE_API_URL`: the Render API URL plus `/api`, such as `https://codereview-api.onrender.com/api`

Redeploy after setting the environment variable. `VITE_API_URL` is included in the public frontend bundle and must only contain the API base URL, never a secret.

## 4. Verify the deployment

1. Open `<render-url>/swagger-ui/index.html` and confirm the API is healthy.
2. Open the Vercel URL, register a developer account, and sign in.
3. Create a review request and confirm it appears in the list.
4. Check the browser console/network panel if a request fails. A browser CORS error usually means `CORS_ALLOWED_ORIGINS` does not exactly match the Vercel origin; update it and redeploy the API.

The API currently uses Hibernate `ddl-auto=update` to create/update the schema at startup. This is convenient for the initial deployment, but a migration tool such as Flyway should be introduced before making production schema changes that require controlled rollbacks. The Render service is configured on the free compute plan, which can spin down when idle and is intended for testing and hobby projects rather than production workloads.
